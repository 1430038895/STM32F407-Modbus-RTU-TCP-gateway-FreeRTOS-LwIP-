# Modbus 寄存器点表说明

本文件说明网关（`mb_gateway.c` 中的 `g_devs[]`）向下行 RS485 从机采集的点表，
以及上行 Modbus TCP 主站如何通过单元号（Unit ID）访问这些数据。

## 1. 缓存模型

```
TCP 主站请求:  Unit ID = 从机站号, 寄存器地址 = 该从机内部寄存器偏移
                         ↓ 互斥锁保护
g_slave_regs[slave-1][0..MB_MAX_REGS-1]   （每从机 64 个 16 位寄存器）
                         ↓ RTU 主站轮询
RS485 总线上的实际从机（站号 1..8）
```

- `MB_MAX_SLAVE = 8`：最多 8 台从机（站号 1~8）
- `MB_MAX_REGS = 64`：每台从机缓存寄存器地址 0..63
- 轮询任务每秒对所有点表条目采集一次，成功后写缓存并标"在线"；失败标"离线"并重试 3 次

## 2. 当前点表（`mb_gateway.c` 中 `g_devs[]`）

| 从机 | 功能码 | 起始地址 | 数量 | 数据类型 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 从机1 | 0x03（保持寄存器） | 0 | 2 | DT_U16（无符号16位） | 2 个 16 位寄存器，缓存为 reg0..1 |
| 从机2 | 0x03（保持寄存器） | 0 | 2 | DT_F32_ABCD（32位浮点，高字在前） | 1 个 32 位浮点，占用 reg0..1 |

> 增加新设备只需在 `g_devs[]` 末尾追加一行，例如：
> ```c
> { .slave = 3, .func = 0x03, .reg = 0, .count = 4, .type = DT_U16 },
> ```
> 约束：`reg + count <= MB_MAX_REGS`，`count <= 16`。

## 3. 数据类型与字序

| 枚举 | 含义 | 占用寄存器 | 说明 |
| --- | --- | --- | --- |
| DT_U16 | 无符号 16 位 | 1 | 每个寄存器一个数 |
| DT_S16 | 有符号 16 位 | 1 | 符号扩展存入缓存 |
| DT_F32_ABCD | 32 位浮点，高字在前 | 2 | 第 1 个寄存器为高 16 位 |
| DT_F32_CDAB | 32 位浮点，低字在前 | 2 | 缓存时自动交换为高字在前 |

> 32 位数据在缓存中统一按"高字在前"存放，是否按浮点解释由上位机决定。

## 4. 上行 TCP 主站访问方法

用 MThings（或任意 Modbus 主站工具）以 **Modbus TCP** 连接：

| 参数 | 值 |
| --- | --- |
| 目标 | 板卡 IP（DHCP 或静态配置见 `lwip.c`） |
| 端口 | 502 |
| Unit ID | 目标下行从机站号（1~8） |
| 功能码 | 0x03 读保持寄存器 |
| 地址 | 该从机内部的寄存器偏移（0 起） |

示例：读从机 2 的浮点 → TCP 请求 Unit ID=2、功能码 0x03、地址 0、数量 2，
返回两个寄存器按 `ABCD`（高字在前）拼成 float。

## 5. 写操作

- 单寄存器写：功能码 0x06，**写穿透**到下行 RTU 从机，成功后同步更新缓存
- 多寄存器写：功能码 0x10，同理写穿透并更新缓存
- 下行从机不可写（或地址只读）时返回失败，缓存不更新

## 6. 在线状态

- 通过 TCP 读到的寄存器数值为最后一次成功采集的缓存快照
- 从机离线时缓存保留旧值；可通过日志串口（USART1 @ 115200）观察 `[RTU] slave=N OFFLINE` 提示
